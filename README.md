# nmd

دستیار اجرایی فایل و داده. در نسخه اول، هسته محصول Excel است: فایل وارد می‌شود، ساختارش خوانده می‌شود و نسخه اصلی دست‌نخورده می‌ماند.

این مخزن الان Part 1 را دارد: ورود `xlsx`، `xls` و `csv`. پاک‌سازی، تطبیق، تحلیل و گفتگو در این بخش نیستند.

## Part 1 چه می‌کند

- یک یا چند فایل را می‌پذیرد.
- نوع‌های بعدی (`pdf`، `docx`، تصویر) در رجیستری ثبت شده‌اند و در این نسخه غیرفعال‌اند.
- نسخه `original` با شماره `0` را یک‌بار می‌نویسد و بازنویسی نمی‌کند.
- خلاصه ساختاری برمی‌گرداند: نام شیت، عنوان ستون‌ها، تعداد ردیف غیرخالی و تعداد ردیف داده.
- فایل خراب، خالی، نوع نامعتبر یا بزرگ‌تر از حد را بدون ذخیره رد می‌کند.

آپلود مجدد، سند تازه‌ای می‌سازد و بایت‌های نسخه قبلی را عوض نمی‌کند.

## فرض‌ها

- وب‌اپ تک‌کاربره، بدون احراز هویت.
- Backend با Python 3.12 و FastAPI. Frontend با Next.js.
- فراداده در SQLite و فایل‌ها روی دیسک محلی.
- سقف پیش‌فرض: ۲۰ مگابایت برای هر فایل، ۱۰ فایل در هر ارسال، ۱۰۰ شیت، ۲۰۰٬۰۰۰ ردیف غیرخالی در هر شیت، ۵۱۲ ستون، ۲۰۰ مگابایت محتوای غیرفشرده برای xlsx.
- عنوان‌های طولانی‌تر از ۵۰۰ نویسه فقط در خلاصه کوتاه می‌شوند. فایل اصلی کامل می‌ماند.
- ردیف کاملاً خالی در شمارش نمی‌آید. اولین ردیف غیرخالی عنوان است.

## اجرا

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```bash
cd frontend
npm install
npm run dev
```

رابط روی `http://127.0.0.1:3000` است و `/api` را به Backend می‌فرستد.

## API

- `GET /api/health`
- `GET /api/file-types`
- `POST /api/uploads` با فیلد چندتایی `files`
- `GET /api/documents`
- `GET /api/documents/{id}`

مسیر ذخیره و محتوای ردیف‌ها در پاسخ API نیست.

## بررسی

```bash
cd backend && .venv/bin/pytest && .venv/bin/ruff check . && .venv/bin/mypy
cd frontend && npm run typecheck && npm run lint && npm run build
```
